# Transfer Queue

Serialize bounded transfers through a private local queue. HTTPS downloads require an expected SHA-256 and can resume using a stable strong ETag and byte ranges. For uploads, register an **already-created tus 1.0 HTTPS upload URL**, then send one small chunk per explicit call. A separate explicit `transfer_upload_preflight` sends only HEAD to check remote length and offset before transferring any file bytes; it reports uncertainty without changing the job. The plugin checks the remote offset, limits each chunk, remembers uncertain outcomes and reconciles them before another explicit send. It records a local source SHA-256 and refuses to continue if the source changes. List local jobs to recover their IDs without contacting a server or showing source paths.

Uploads require a tus resource whose declared length matches the source and whose offset starts at zero. No authentication, signed URL query strings, redirects, upload creation, background scheduler or automatic retry is supported. The remote server's acknowledged offset does **not** prove its content matches the local checksum; verify independently at the destination. Only supply URLs and files you intend to send to trusted servers. Rate controls pace this plugin's chunks, not all network buffering or other applications' traffic. Jobs and downloaded content remain in the private Hermes plugin data directory until removed.

Both directions are limited to 512 MiB, use HTTPS without embedded credentials or query strings, and bypass proxy configuration. Download servers need a content length and strong ETag for resume. Eleven tests include a loopback TLS tus server and interrupted-response reconciliation; an independently checksum-verified real 29,502-byte HTTPS download also passed with a 206 resume response. No public upload, authenticated server, bandwidth measurement, or production destination has been tested. Protocol: https://tus.io/protocols/resumable-upload

The Hermes Desktop page supports job creation, listing and reconnecting to local jobs, explicit slice execution and status checks. Reconnecting clears the URL, which must be supplied again before a transfer. Uploads are not sent until an explicit run action; uncertain outcomes are displayed. Functional Desktop/API tests pass, while native visual review remains pending.

To upload selected media already under the active profile's plugin-data directory, explicitly enable `allow_profile_media`. This opt-in is limited to supported media extensions in that profile; unrelated private configuration remains blocked. Apply the full release audit to any material before public upload.
